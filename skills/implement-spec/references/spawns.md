# Spawn briefs

The shared rules (Question, 60-line cap, malformed block, fallback) are in `SKILL.md` `## Spawn briefs`.

- **Explorer** brief for `locate`: kind `locate`, the absolute root, the requirement (the requirement text, file path, or URL with its fetched text; a URL is read only from the text supplied). Return: `Target:`, `Refs:` (`- <path>:<line> — <what it shows>`), `Question:` only when needed. A `Question:` return → ask the user and re-spawn with the answer (counts toward the `Question:` or `blocked` cap; `--yes`: the needs-input rule in `SKILL.md` Flags). A malformed block → respawn once, then the inline fallback: locate the affected code and return the same fields; a subagent unavailable → the same inline fallback with Read, Glob, Grep, no failure. Brief and Return for `leftovers`: `validate.md` Leftover search.
- **Verifier** brief: kind `goals`, root, restated requirement, goals with acceptance criteria and `Edges`, non-goals, the chosen approach, the planned file list (union across rounds, `validate.md` Change-set check), changed paths. Bash only for read-only `git` (`diff`, `status`, `log`, `show`) and the project's documented test, type check, and build commands (`SKILL.md` Rules); never a write mode (`--fix`, `--write`, snapshot updates), a rewriting formatter, an install, or a network deploy. It reviews the changed files for correctness bugs, regressions, unplanned files, and behavior changes without a test, an edge with no test, and a new or changed test assertion that would still pass with the change reverted (a judgment from the diff, never an executed revert; each is a `major` finding with `path:line`); a change that serves a non-goal or a path outside the planned list is `major`; runs the new or changed tests, then type check, tests, and build where documented (kind `goals` skips the format check and lint, which repo hooks and CI own; never a formatter or linter), running test commands non-interactively (`CI=true`, never watch mode), and a command that hits the 10-minute cap is `skipped (timeout)` and is not re-run for the rest of the run; in baseline mode (changed paths `none (baseline)`) it reports `Checks:` only; judges each goal `met` (behavioral goals need a passing test that exercises it), `unmet`, or `unverified` (`unverified — no test` when only code reading supports a behavioral goal) with `path:line` or command evidence; a check it cannot run is `skipped (<reason>)`, never reported as pass. Return: `Status: pass | fail | blocked`, `Goals:` (each `met | unmet | unverified` with evidence), `Findings:` (`<id> [blocker | major | minor] <path>:<line> — evidence; fix: recommendation`), `Checks:` (`<command> [required] → pass | fail (exit <n>) | skipped (<reason>)`, first failing lines and `Failing tests:` (every failing test ID, or `none reported`) for a fail), `Limitations:`, `Question:` only when needed. Fallback: do the same inline and mark any goal not proven `unverified`. `Limitations:` → `Open:`.
