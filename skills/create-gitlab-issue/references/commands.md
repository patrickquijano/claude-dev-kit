# Commands

`<host>`, `<url>`, `<enc>`, `<iid>`, `<default>`, `<path>`, `<title>`, `<file>`, `<label>`, `<query>` are literal values from Input and earlier steps (see `gitlab-mapping.md`). Titles and bodies never go inline in a shell argument; the description goes to a scratch file (`--description-file`), and only a title or label with no quotes, metacharacters, or control chars goes inline in `'<title>'`; any other goes through MCP or is asked. MCP names are hints: discover the real ones at runtime with ToolSearch (`gitlab work item`, `gitlab label`, `gitlab repository`); `—` = no MCP tool. Run `glab <command> --help` before the first use of each glab command.

| Name              | MCP tool (hint)                                                                                                       | Command (`glab` fallback)                                                                                                                                                                                                                                                   | Purpose                                                                                     |
| ----------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `auth`            | —                                                                                                                     | `glab auth status --hostname <host>`                                                                                                                                                                                                                                        | Must succeed in the fallback, else tell the user to run `glab auth login --hostname <host>` |
| `origin`          | —                                                                                                                     | `git remote get-url origin`                                                                                                                                                                                                                                                 | Host and project path of the working directory                                              |
| `default-branch`  | —                                                                                                                     | `git symbolic-ref --short refs/remotes/origin/HEAD`                                                                                                                                                                                                                         | Template branch: output minus `origin/`; failure → ask                                      |
| `project-get`     | `mcp__plugin_gitlab_gitlab__get_project`                                                                              | —                                                                                                                                                                                                                                                                           | MCP host check (`gitlab-mapping.md`)                                                        |
| `issue-get`       | `mcp__plugin_gitlab_gitlab__get_work_item` (`url` or `project_id` + `iid`)                                            | `glab issue view <iid> -R <url> -F json`                                                                                                                                                                                                                                    | Current title, description, labels, type, state                                             |
| `issue-search`    | `mcp__plugin_gitlab_gitlab__list_work_items` (`search`, `state: opened`, `types: [ISSUE]`)                            | `glab issue list -R <url> --search '<query>' --in title -O json`                                                                                                                                                                                                            | Open duplicates before a create                                                             |
| `template-lookup` | `mcp__plugin_gitlab_gitlab__list_repository_tree` + `mcp__plugin_gitlab_gitlab__get_repository_file` (default branch) | `node ${CLAUDE_SKILL_DIR}/scripts/glab-get.mjs <host> 'projects/<enc>/repository/tree?path=.gitlab/issue_templates&ref=<default>&per_page=100'`, then `node ${CLAUDE_SKILL_DIR}/scripts/glab-get.mjs <host> 'projects/<enc>/repository/files/<enc-file>/raw?ref=<default>'` | List the template directory, then read one file (`<enc-file>` = URL-encoded path)           |
| `label-list`      | `mcp__plugin_gitlab_gitlab__search_labels` (`full_path`, `is_project`)                                                | `glab label list -R <url> -F json -P 100`                                                                                                                                                                                                                                   | The project's own label set                                                                 |
| `work-item-types` | `mcp__plugin_gitlab_gitlab__get_work_item_types`                                                                      | —                                                                                                                                                                                                                                                                           | Valid types; no route → `Issue`                                                             |
| `label-create`    | —                                                                                                                     | `glab label create -R <url> -n '<label>'`                                                                                                                                                                                                                                   | Write, asked: create a missing label (`glab` only)                                          |
| `create`          | `mcp__plugin_gitlab_gitlab__save_work_item` (no `work_item_iid`; `type_name`, `title`, `description`, `labels`)       | `glab issue create -R <url> -t '<title>' --description-file <file> [-l '<label>']... -y`                                                                                                                                                                                    | Write: open the issue                                                                       |
| `update`          | `mcp__plugin_gitlab_gitlab__save_work_item` (with `work_item_iid`; `add_labels`, `remove_labels`)                     | `glab issue update <iid> -R <url> -t '<title>' --description-file <file> [-l '<label>']... [-u '<label>']...`                                                                                                                                                               | Write: replace title and description, change labels                                         |

Step 1 records, per operation, whether it runs on MCP or `glab`. `Tool:` reports `mcp`, `glab`, or `mcp+glab:<ops on glab>`.
