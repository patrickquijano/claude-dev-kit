# Commands

`<root>` is the repo root; `<run>` is the absolute `run` value that `init` prints, a directory under `<root>/.cdk-security-audit/`, which `init` makes self-ignoring for git. `<path>` is a repo-relative path prefix.

| Name       | Command                                                                                                                                   | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Exit codes                                                                                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `root`     | `git rev-parse --show-toplevel`                                                                                                           | Repo root (preloaded in Context)                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 0 ok; 128 not a repo → stop                                                                                                                                           |
| `init`     | `node ${CLAUDE_SKILL_DIR}/scripts/audit-records.mjs init --root <root> [--profile quick\|standard\|deep] [--range <a>..<b>] [<path> ...]` | Create the next `run-<n>` dir and write `scope.json`; prints `run`, `head`, `profile`, `range`, and the `files`, `out_of_scope`, and `sensitive` counts (the paths are in `scope.json`; `sensitive` lists tracked secret-named files such as `.env` or `*.pem`, and tracked symlinks whose target is outside the repo, under `.git`, secret-named, or unresolvable, kept out of `files`); a range diffs from the merge base of `<a>` and `<b>`; `--range` needs `<b>` to resolve to `HEAD` (exit 2 otherwise) | 0 ok; 1 runtime error (stderr `audit-records: <msg>`), including a run directory not ignored by git → safety stop; 2 usage, including a path matching no tracked file |
| `ledger`   | `node ${CLAUDE_SKILL_DIR}/scripts/audit-records.mjs ledger --run <run>`                                                                   | Check `ledger.json` against `scope.json` (L0 to L6: L0 malformed unit, L1 duplicate id, L2 coverage value, L3 file in no unit or in more than one, L4 over 40 covered or deferred units, L5 path outside scope, L6 out-of-scope path in no out_of_scope unit)                                                                                                                                                                                                                                                 | 0 `ok:true`; 1 `ok:false` with `errors`; 1 runtime error; 2 usage                                                                                                     |
| `findings` | `node ${CLAUDE_SKILL_DIR}/scripts/audit-records.mjs findings --run <run>`                                                                 | Check `findings.json` against `assets/report-schema.json` and rules F1 to F9                                                                                                                                                                                                                                                                                                                                                                                                                                  | 0 `ok:true`; 1 `ok:false` with `errors`; 1 runtime error; 2 usage                                                                                                     |

Single-quote each `<path>`, `<run>`, `--profile`, `--range`, and `--root` value in a command; the script rejects a `--profile` outside `quick`, `standard`, and `deep` with exit 2; a value containing `'` → `Result: stopped`.

Exit 1 with `{"ok":false,"errors":[{"rule","id","message"}]}` on stdout from `ledger` or `findings` is a check result, not a stop: fix the named records and run it again. Exit 1 with a single `audit-records: <msg>` line on stderr is a runtime error: stop and report it.
