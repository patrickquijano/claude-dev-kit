# CDK — Claude Dev Kit

Claude Code plugin providing a development kit — skills, custom agents, and hooks — for any framework or language.

Adds guided Git and GitHub workflows (signed atomic commits, rebases, issues, pull requests, reviews, releases) plus skill, README, and CLAUDE.md authoring with scored rubrics, so Claude follows the same conventions in every repository.

> **Status:** pre-1.0 (v0.9.6). This repo changes a lot: skills, agents, and hooks may be renamed or removed in any minor release, so pin a version. Breaking changes are listed in [CHANGELOG.md](CHANGELOG.md).

## Compatibility

- [Claude Code](https://code.claude.com/docs) CLI (`claude`).
- Git; commit and rebase skills sign commits when signing is configured. `/cdk:setup-git` SSH signing needs Git 2.34+; OpenPGP needs GnuPG.
- [`glab`](https://gitlab.com/gitlab-org/cli) CLI, authenticated, optional: `/cdk:commit-changes` and `/cdk:rebase-onto` use it to look up GitLab protected branches and merge requests; the GitLab merge request skills and `/cdk:create-gitlab-issue` use it when the GitLab MCP server is not connected.
- [`gh`](https://cli.github.com/) CLI, authenticated, for the pull request skills, `/cdk:create-github-release`, and `/cdk:create-github-issue` when the GitHub MCP server is not connected.
- GitHub and GitLab MCP servers optional: skills call their tools first and fall back to `gh`/`glab` when a server is not connected or errors.
- [`uv`](https://docs.astral.sh/uv/) for `/cdk:setup-spec-kit` when `specify` is not installed.
- [`uv`](https://docs.astral.sh/uv/) or `pipx` (Python 3.10+) for `/cdk:setup-graphify` when `graphify` is not installed.
- Node.js with npm, pnpm, yarn, or bun for `/cdk:setup-husky`, `/cdk:setup-nextjs-app` (Node.js at least the version in Next.js `engines.node`), and the npm tools of `/cdk:setup-formatters` and `/cdk:setup-linters`; Node.js alone for `/cdk:update-statusline`. Node.js 22 or newer for `/cdk:audit-code-security`. Node.js 20.1 or newer for `/cdk:update-rules`.
- The project's package manager for `/cdk:upgrade-dependencies`.
- The .NET SDK (`dotnet`) and `curl` for `/cdk:setup-dotnet-api`; PHP and Composer for `/cdk:setup-laravel-api`.
- [`uv`](https://docs.astral.sh/uv/) (`uvx`) or `pipx` optional for `/cdk:update-dependabot` schema checks; without either it uses a manual checklist.
- Docker for `/cdk:build-dockerfile` build checks; `hadolint` optional.
- `/cdk:build-github-workflow` and `/cdk:build-github-action`: authenticated [`gh`](https://cli.github.com/) optional for action and release lookups; [`actionlint`](https://github.com/rhysd/actionlint) optional for validation; Docker optional for a Docker action's build check.
- `/cdk:build-gitlab-ci`: authenticated `glab` or a `GITLAB_TOKEN` optional for CI Lint validation; the token is sent only to the host in `GITLAB_HOST`, or to gitlab.com when `origin` is gitlab.com, so set `GITLAB_HOST` for a self-managed instance; falls back to `yamllint` or Python 3 with `yaml`.
- Docker for `/cdk:setup-devcontainer` Compose checks; [`@devcontainers/cli`](https://github.com/devcontainers/cli) optional for `devcontainer read-configuration`.
- Docker for `/cdk:setup-local-sonarqube` (the generated `compose.sonar.yaml` runs the SonarQube server and scanner as containers; no host install).
- Development only: Node.js >=22 with npm, `yamllint` and `yamlfmt` on `PATH`; `hadolint` optional (hook lints Dockerfiles when present).

## Install

```sh
claude plugin marketplace add https://github.com/patrickquijano/claude-dev-kit.git
claude plugin install cdk@claude-dev-kit
```

## Components

### Skills

A skill that reports findings (failed or skipped checks, gaps, open items) runs its own capped fix loop where it needs one and lists what is left under `Open:` before `Result:`. Every skill takes `--yes` (unattended: no questions, recommended options taken, assumptions listed under `Open:`). Where no safe default exists, `--yes` does nothing: `/cdk:delete-branches` selects no branch, `/cdk:rebase-onto` aborts at the first conflict and skips the push, and `/cdk:audit-code-security` takes `Report only` and fixes nothing. A skill may run another skill. Only `/cdk:switch-branch` switches or creates a branch and only `/cdk:commit-changes` commits; other skills run those two instead, except that `/cdk:rebase-onto` replays existing commits.

### Hooks

| Event                      | Script                            | Purpose                                                                                                                                                    |
| -------------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PostToolUse` (Write/Edit) | `hooks/scripts/post-tool-use.mjs` | Format, then lint each file Claude edits with the repo's configured tools; failures go back to Claude as context, never blocking.                          |
| `Stop`                     | `hooks/scripts/stop.mjs`          | Format, then lint the whole repo with the same tools, per file type, only when that type's files changed; feeds errors and warnings back to Claude to fix. |
| `SessionStart`             | `hooks/scripts/session-start.mjs` | Inject today's date and time.                                                                                                                              |

### Hook flow

How the hooks fire across a session:

```mermaid
flowchart TD
    A["SessionStart: inject date and time"] --> K["PostToolUse on Write or Edit: format, then lint each file"]
    K --> L["Stop: format, then lint the repo per changed file-type group"]
    L --> M{"Errors or warnings left?"}
    M -- yes --> N["Feed back to Claude"]
    M -- no --> O["Turn ends"]
```

### Example

In a Claude Code session inside your repository:

```text
/cdk:update-readme score
```

Claude scores the existing `README.md` against the 100-point rubric and prints a per-criterion table with deductions. Score mode never writes files.

## Versioning and changelog

User-facing changes need a new `Unreleased` entry in `CHANGELOG.md`. The version level comes from the branch commits: breaking = major, `feat` = minor, otherwise patch. While the major version is 0, a breaking change bumps minor and everything else bumps patch; standard SemVer applies from 1.0.0. A version bump needs your confirmation and happens only for a PR or MR: edit the version in `.claude-plugin/plugin.json`, then run `/cdk:update-changelog`.

Releases: pushing a version tag (`vX.Y.Z`) runs [`.github/workflows/release.yml`](.github/workflows/release.yml), which publishes the GitHub release from that version's `CHANGELOG.md` section (a prerelease when the tag has a `-` suffix).

Breaking changes (mark the commit with `!`): renaming or removing a skill, slash command, or agent; changing a skill's arguments or required inputs, or an agent's `## Return` format callers parse; a hook that newly blocks, or a change to what it blocks; raising the minimum tool versions in Compatibility.

## Contributing

- Commits: signed, Conventional Commits subject only, ≤72 characters. Husky `commit-msg` runs commitlint; check a message with `npx commitlint --edit <file>`.
- Branches: `<type>/<short-description>`.
- Never bypass hooks with `--no-verify`.
- CI: pull requests to `main` run [`.github/workflows/lint.yml`](.github/workflows/lint.yml) (`npm run lint`, with `yamllint` 1.38.0 and `yamlfmt` v0.21.0).
- Open pull requests with the [default template](.github/pull_request_template.md).
