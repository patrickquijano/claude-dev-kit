# Skills

- One skill per `skills/<name>/SKILL.md`; `name` = directory, kebab-case.
- `description` = trigger: what it does + when to use, key use case first. Description + `when_to_use` max 1,536 chars.
- `SKILL.md` under 500 lines. Reference material → sibling files, link them (progressive disclosure).
- Never set `disable-model-invocation`, never ask about it or offer it as an option; side-effect skills gate on description (`Use only when the user explicitly asks ...`). Only exception: user explicitly asks to disable model invocation for that skill. Skills chained by other skills via the Skill tool never set it (blocks the chain).
- Skills that chain skills, and the skills they chain, never set `context: fork`; chain via the Skill tool in the main thread, never the Agent tool, so no subagent nests another (`build-skill/references/orchestration.md`).
- Pre-approve only needed tools via `allowed-tools`. Never pre-approve `git push`, MR create/update, or comment, approve, resolve, merge endpoints; permission prompt = second guard. Never pre-approve a `glab api` or `gh api` pattern ending in `*`: flags appended after it (`-X PUT`, `-f`) turn the read into a write.
- Frontmatter order: `name`, `description`, `argument-hint`, `allowed-tools`, `disable-model-invocation`.
- Body: `Input: $ARGUMENTS` (omit when no input), `## Rules`, `## Workflow` (numbered steps, bold labels `**Pre-flight.**`), `## Output` (fenced `text`, ends `Result: done | nothing-to-do | stopped | cancelled` + `Stopped: <step>: <reason> | none`).
- Every loop and retry states its cap in Rules. Side-effect confirmation options name each effect ("Commit + push").
- Every skill whose Output reports findings (failed or skipped checks, gaps, suspected bugs, blockers, open items) has a `**Resolve findings.**` workflow step, after any own capped loop and last before any `**Report**` step (`scan-vulnerabilities` runs it after its Ship step, which supplies `Manual actions:`), that links `build-skill/references/resolve-findings.md` (`scope: edit | ask-only`, `sources` covering every Output field that reports failures, skips, gaps, or open items), and adds `Resolution:` (never `Findings:`, which review skills use for their own tally) immediately before `Result:` in Output. A skill with its own capped fix-and-ask loop keeps it and still runs the step once after it, never re-entering the loop; never duplicate the procedure inline. Only `switch-branch` omits the step, as it has no findings. Unattended runs (chained, `--auto`, `--yes`, or invoked by the cdk Stop hook) ask nothing and report what is left.
- Shared rules: third occurrence → sibling file, linked `${CLAUDE_SKILL_DIR}/../<skill>/<file>` (e.g. `commit-changes/references/conventions.md`).
- Use `$ARGUMENTS` / `${CLAUDE_SKILL_DIR}` substitutions, not hard-coded paths.
- Known issues never live in the repo (no `SKILL.md`, no `## Known issues` section). Skill-scoped ones go to `${CLAUDE_PLUGIN_DATA}/known-issues/<skill>.md` (shared across projects, survives updates); project-scoped ones go to Claude auto memory (`feedback` memory + `MEMORY.md` pointer). `${CLAUDE_PLUGIN_DATA}` is substituted only in skill and agent markdown, so each Rules section links `build-skill/references/known-issues.md` with its slug and store.
- Shared files: `build-skill/references/known-issues.md`, `build-skill/references/fallbacks.md` (no AskUserQuestion/Write), `build-skill/references/resolve-findings.md` (final findings step), `build-agent/references/practices.md` (subagent drafting), `build-skill/references/orchestration.md` (skills chaining `cdk:` skills), `commit-changes/references/conventions.md` (git), `prepare-change-request/{github,gitlab}.md` (gh/glab pre-flight, identity, managed section, API rules; also used by `review-change-request` and `address-change-request-review`), `prepare-change-request/references/release-gate.md` (changelog and version gate before PR/MR creation), `prepare-change-request/references/findings.md` (CR reviewer output contract, `## Direct review` for small changes, shared with `review-change-request`), `review-change-request/references/guidelines.md` (comment labels and approval criteria, also used by `address-change-request-review`), `address-change-request-review/references/state.md` + `{github,gitlab}.md` (feedback items, state, host mutations), `address-change-request-review/references/replies.md` (reply templates), `setup-spec-kit/references/speckit-chain.md`, `setup-husky/references/package-manager.md`, `setup-husky/references/ignores.md` (linter, formatter, Docker ignore syntax), `setup-test-hook/references/stacks.md` (runner detection), `write-unit-tests/references/conventions.md` (test-writing skills), `write-dockerfile/references/practices.md` (base image tag resolution, also followed by `write-github-workflows/references/versions.md` for container and service images). Link them; never copy their rules.
- Verify: `plugin-dev:skill-reviewer` + `cdk:skill-auditor` agents + `claude plugin validate --strict .`; never run LLM-graded `claude plugin eval`.
